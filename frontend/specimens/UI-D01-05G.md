## Defect and exact production change

The public content catch-all maps `teachers` to TeacherDirectory. SiteNavigation previously used `pathname.startsWith(\`/${locale}/teacher\`)`for both workspace and account-area classification. That incorrectly included`/teachers`, suppressed public query eligibility and could redirect a resolved guest to Login.

Only `src/components/site-navigation.tsx` changes production code: a private `isTeacherWorkspacePath` predicate builds `sectionRoot = /{locale}/teacher`, then requires `pathname === sectionRoot || pathname.startsWith(sectionRoot + "/")`. Exactly the workspace and isAccountArea checks call it. No other Teacher classification check exists in that file.

Real `/teacher` and its descendants retain their existing protected/account-area behavior. `/teachers`, classification-only nested/colliding inputs and `/teacherish` cannot acquire Teacher workspace/account status from the textual prefix. No production route is invented for negative classification tests.

All other SiteNavigation bytes return to the independently verified main hash through an exact helper/two-call-site projection. Original #196 protected-file fixtures/hashes remain unchanged; its test applies this narrow projection only to SiteNavigation. Negative mutations reject naive prefix matching, unconditional matching, drift in either call site, query keys, destination hrefs, other-role classification, taxonomy enabling and locale hash handling. No arbitrary source fragment is erased.

Admin/Support/Student predicates, role registry, destinations, branding/account decisions, query keys/options/API paths, logout/redirect implementation, locale/query/hash handling, translations, shared primitives, fonts/tokens, dependencies, proxy/backend and AI/RAG are unchanged.
